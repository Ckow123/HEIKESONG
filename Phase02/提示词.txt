## 二、先解决朋友电脑上的工程环境

这里需要区分两个概念。

- 项目代码存在：仓库中有 `app/src/`、`package.json`、`package-lock.json`。
- 项目依赖已安装：朋友电脑的 `app/node_modules/` 内有与锁文件匹配的可用依赖。

React、Vite、TypeScript、Tailwind 不需要逐个进行全局安装。通常只需在正确的 `app` 目录执行一次 `npm ci`，即可按照现有锁文件安装项目依赖。

当前 Vite 8 要求 Node.js 20.19+ 或 22.12+ 的兼容版本。

## 五、如何进一步节省 Token？

真正节省 Token 的方法不是让很多模型同时运行，而是避免它们反复读取同样的文件和互相覆盖。

- 主 Agent 只需一次读取五份任务文件，向子 Agent 传递各自有关的任务与接口契约。
- UI Agent 负责有视觉输入的任务，不需要阅读完整历史 JSON。
- 测试 Agent 只读取测试任务、对应业务规则和所测源码，不参与产品方案讨论。
- 不对已经稳定的功能无差别重新设计，优先修复已知缺陷。

还要强调一件事：`frontend-design` 负责改善视觉质量，但它不会自动让业务功能变完整。使用 Skill 时仍要让 WorkBuddy 验证是否实际加载，并保留使用记录。

1. 将五份任务 MD 复制到朋友实际使用的 WorkBuddy 工程中。

5. 每个批次保留 WorkBuddy 报告和真实截图，再交给我核对，无需每次重新启动 Codex。

拿到 WorkBuddy 的环境检查和 Plan 结果后，再正式批准 Agent 执行，能最大程度减少返工。
