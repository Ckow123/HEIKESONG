## 真实交互问题与需要实现的最小改动

### UI-01a 首页搜索（P1，可直接做）

证据：`DiscoveryPage.tsx:26–33` input 无value/onChange/form处理；:96固定slice(0,3)、:126全量活动。搜索不会产生结果变化。

最小工程方案：仅本地字符串匹配，不增加API/推荐算法。输入去首尾空格、英文不区分大小写；匹配**已确认公开**的昵称/兴趣，以及现有活动标题/描述/类别。结果在现有首页内容区显示人/活动两组，并给出数量；保留两个入口与整行星云的结构，不创建新一级导航。查询命中全部公开池，不能只搜推荐的前三人。空查询恢复现有推荐/活动布局；无结果显示可理解提示和清空入口，Enter与搜索按钮行为一致，输入有label。

这些是完成已提出任务的最小实现建议，不变更公开范围。A先与主Agent约定公共selector，不能读取 `state.portraits` 自己过滤来绕过01的公开确认版。

### UI-01b 活动分类（P1，可直接做）

证据：`ActivitiesPage.tsx:8,20–26` 分类用 `Tag`；`app/src/shared/ui/Tag.tsx:12–17` 是span且无事件；代码注释:10的“展示过滤”未实现。

最小方案：保留“全部活动 / 运动 / 学习 / 语言 / 比赛”，用页面内button控制单选类别，Tag仍可作视觉子元素；支持键盘、focus、aria-pressed，显示真实筛选结果及空状态，“全部活动”恢复四条基准数据。只从现有Activity.interestCategory筛选，不解析timeText、不扩展日期地点排序或收藏。类别状态可留页面内，不修改全局模型/路由。

### UI-02 视觉与响应式（P2，访问可用性P1）

- 沿用 `app/tailwind.config.js:6–20` 蓝紫/薄荷/浅底/18px圆角，当前已有设计系统基础，不能称“完全不符原图”。建议统一hero标题、分区标题、卡片标题、元数据和CTA层级；主Agent拥有全局tokens/shared，A提交精确建议。
- 为现有页面提供校园插图/封面层次，图像作为辅助，兴趣/意图与文字仍为主体。复用原图视觉语言和可用合成资产；不采集真人照片，不新增未确认资料字段。新资产只放A独占的本地目录，说明来源。
- 手机保持底部四栏：**发现 / 广场 / 信息 / 我的**；桌面保持DEC-006顶部导航；发现始终两个并列入口，下一行独占星云。不新增第五栏、不迁移星云到一级导航、不将全站改深色星空。
- 行星可点击、标签不与底部说明相互遮挡；无鼠标时可触达；不擅改主Agent的公开投影算法或加MBTI距离算法。
- 未实现业务使用清楚的演示/待实现标注；不可用高仿成功toast、可点但无业务的“拒绝/报名/发起活动/收藏”等装饰控件制造完成印象。
